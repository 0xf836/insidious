# Requirements

## Источники изображений

Программа должна уметь открывать:

- отдельный файл изображения;
- несколько выбранных файлов изображений;
- папку с изображениями;
- архив с изображениями;
- файл, папку или архив через drag'n'drop.

Если пользователь открыл один файл из папки, программа должна воспринимать родительскую папку как контекст просмотра и позволять переключаться на соседние изображения.

## Базовый просмотр

Программа должна поддерживать:

- отображение текущего изображения в окне;
- переход к следующему и предыдущему изображению;
- масштабирование;
- режим `fit to window`;
- режим `actual size` / 100%;
- поворот изображения на 90° влево и вправо без изменения исходного файла;
- fullscreen;
- перетаскивание изображения мышью при увеличении;
- сброс масштаба и позиции.

## Навигация

Требования к навигации:

- клавиши вперёд/назад;
- колесо мыши переключает изображения вперёд/назад;
- `Ctrl + wheel` управляет zoom;
- возможность настроить масштаб увеличения по умолчанию;
- простой клик левой кнопкой мыши включает временное приближение к масштабу по умолчанию с центровкой по точке клика;
- повторный простой клик левой кнопкой мыши после click zoom или rectangle zoom возвращает исходный режим `fit` или `actual size`;
- зажатая левая кнопка мыши включает режим перетаскивания изображения рукой;
- зажатая правая кнопка мыши задаёт прямоугольник для zoom-to-selection;
- отображение номера текущего изображения и общего количества, например `12 / 240`;
- отображение имени текущего файла;
- переход к первому и последнему изображению;
- навигация по панели миниатюр;
- навигация по панели списка файлов;
- быстрый переход по имени файла.

Для MVP схема мыши зафиксирована так: wheel переключает изображения, `Ctrl + wheel` меняет zoom, простой клик ЛКМ включает временный zoom 200% или возвращает исходный `fit`/`actual size`, левая кнопка при удержании двигает изображение, правая кнопка при удержании задаёт прямоугольник приближения.

## Сортировка

Программа должна сортировать изображения в естественном порядке.

Режимы сортировки:

- по имени;
- по дате изменения.

Для архивов сортировка по дате может быть ограничена доступными metadata внутри архива. Если дата недоступна, используется сортировка по имени.

## Форматы изображений

Целевой список форматов:

- JPEG;
- PNG;
- WebP;
- GIF;
- BMP;
- TIFF;
- AVIF;
- JPEG XL;
- RAW.

Практическое разделение:

- базовые форматы должны быть реализованы раньше;
- AVIF, JPEG XL и RAW следует рассматривать как отдельные этапы из-за зависимости от библиотек, качества декодирования и edge cases.

## Архивы

Программа должна уметь открывать архив как коллекцию изображений.

Минимальные архивные форматы:

- ZIP;
- RAR;
- 7Z.

Требования:

- пользователь открывает архив;
- программа показывает первое изображение внутри архива;
- можно переключаться на следующие/предыдущие изображения внутри архива;
- неизображения внутри архива игнорируются;
- изображения сортируются по имени или выбранному режиму сортировки;
- архив не должен распаковываться на диск в нормальном режиме;
- архивы с паролем должны поддерживаться;
- пароль не должен сохраняться.

## Drag'n'drop

Программа должна принимать через drag'n'drop:

- один файл изображения;
- несколько файлов изображений;
- папку;
- архив.

Поведение:

- если брошен один файл изображения — открыть его и использовать родительскую папку как контекст просмотра;
- если брошена папка — открыть первое изображение в ней и запустить навигацию по папке;
- если брошен архив — открыть изображения внутри архива;
- если брошено несколько файлов — открыть их как временную коллекцию.

## Информация об изображении

Программа должна показывать базовую информацию:

- имя файла;
- формат;
- путь;
- размер файла;
- разрешение;
- дата изменения;
- EXIF.

EXIF должен отображаться в расширенной панели, чтобы не перегружать основной UI.

## Производительность

Производительность — один из ключевых критериев.

Требования:

- быстрое открытие изображений и архивов;
- переключение между соседними JPEG/PNG без заметных подвисаний;
- GUI не должен зависать при открытии большой папки или чтении архива;
- загрузка изображений должна происходить отдельно от UI;
- должен быть memory cache для текущего, предыдущего и следующего изображения;
- приложение не должно бездумно держать всю коллекцию в памяти;
- миниатюры не создаются по умолчанию, только при открытии соответствующей панели.

## Ошибки

Программа должна обрабатывать:

- неподдерживаемый формат;
- повреждённое изображение;
- повреждённый архив;
- архив с неправильным паролем;
- пустую папку;
- пустой архив;
- отсутствие прав на чтение;
- файл, удалённый во время просмотра;
- слишком большой файл или нехватку памяти.

В таких случаях программа не должна падать. Она должна показать понятное сообщение и, если возможно, перейти к следующему файлу.

## Privacy / no traces

Программа не должна вести:

- историю открытых файлов;
- историю открытых папок;
- историю открытых архивов;
- persistent thumbnail cache;
- файловые логи обычного пользовательского режима;
- распаковку архивов на диск в нормальном режиме.

Разрешены настройки приложения, если они не содержат историю просмотренных путей или файлов.
